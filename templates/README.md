# Content templates

Copy a template from this folder into its matching `works/` folder before creating an item. The site does not read templates directly; it reads content in `works/` and the Python build writes the catalogues used by the pages.

## Markdown content

| Template | Use it for | Copy to |
|---|---|---|
| `artwork-template.md` | One artwork or render in the gallery | `works/artworks/<name>.md` |
| `diary-template.md` | A Dear Diary post | `works/diary/<slug>.md` |
| `product-template.md` | One product listing | `works/products/<name>.md` |
| `story-template.md` | A story, fanfiction, or comic listing | `works/stories/<name>.md` |

Edit the values and body marked as examples, including IDs/slugs, descriptions, image paths, alt text, image dimensions, order, and publication settings. Keep the field names, YAML delimiters (`---`), indentation, and required fields. For Diary, keep `published: false` until it is ready. Do not put paid downloads in public assets.

Put images under `assets/img/artworks/`, `assets/img/products/`, `assets/img/stories/`, or `assets/img/diary/<slug>/`. Enter dimensions matching each image. Run `py build_catalogs.py` for artwork, product, and story changes. Diary pages, sitemap entries, and `llms.txt` are generated by `py build_site.py`. Preview the built site from `dist/` using `py -m http.server 8000 --directory dist`.

## Existing JavaScript catalogue snippets

`artwork-catalog-template.js`, `product-catalog-template.js`, and `story-catalog-template.js` preserve the original JavaScript object examples. They are legacy reference snippets; the supported publishing workflow is the Markdown templates above. Do not add catalogue objects directly unless intentionally bypassing the Markdown build.
